# AGENTS.md — kalina_fan_control_v2

## Что это

Прошивка для **ESP-01 (ESP8266)** — дублёр управления вентилятором охлаждения
автомобиля (Lada Kalina). Читает температуру охлаждающей жидкости (ОЖ) с
диагностического адаптера **ELM327 по Wi-Fi (TCP)** и управляет реле вентилятора
по гистерезису.

Один файл: `kalina_fan_control_v2.ino`. Весь код — неблокирующий, на конечных
автоматах (FSM), рассчитан на долгую работу без зависаний.

## Логика работы

- Пока приходит валидная температура ОЖ — вентилятором управляет собственный
  гистерезис (отдельные пороги включения и выключения).
- Если валидных данных нет дольше заданного таймаута — реле снимается и
  управление отдаётся штатному ЭБУ (в чужое управление не вмешиваемся).
  Данные вернулись — снова берём управление на себя.
- Серия неудач ELM — сначала мягкий сброс Wi-Fi, при таймауте Wi-Fi —
  безопасный `ESP.restart()`.
- Детектор «мёртвого TCP»: при серии таймаутов или невалидных ответов подряд
  TCP-соединение принудительно перезапускается.

## Оборудование

- Платформа: ESP-01 / ESP8266.
- Реле на GPIO2, активный уровень HIGH.
  **Внимание:** GPIO2 — boot-strap пин; до `pinMode()` состояние
  неопределённое. Нужен внешний pull-down на транзистор реле, чтобы реле
  гарантированно было выключено при старте.
- Адаптер ELM327 — Wi-Fi точка доступа, TCP `192.168.0.10:35000`.
- Проводка: нормально разомкнутое реле включено параллельно штатному
  управлению ЭБУ, поэтому «relay OFF» = не вмешиваемся.

## Режимы отладки

Задаются макросами в шапке `.ino`:

| Макрос | Поведение |
|---|---|
| `DEBUG_TEMP_EMULATOR` | Эмулятор температуры, Wi-Fi и ELM не задействованы. Периодически бывает «окно сбоя» — для проверки отдачи управления. |
| `WIFI_SCAN_ONLY` | Только сканирование Wi-Fi сетей и печать списка (поиск SSID адаптера). |
| (оба закомментированы) | **Рабочий режим** с реальным железом. |

По умолчанию оба выключены — перед прошивкой проверьте нужный режим.

## Архитектура

Неблокирующие FSM, опрашиваемые из `loop()`: Wi-Fi, TCP/ELM327, опрос PID `0105`.
Каждый автомат — отдельный `*Tick()`, состояние — в перечислении; инициализация
ELM327 идёт по таблице AT-команд. Общая логика вынесена в небольшие хелперы
(реле, таймеры, счётчики неудач, парсер ответа) — при изменениях следовать им,
а не дублировать.

## Сборка и прошивка

Инструменты: `arduino-cli` и PlatformIO (в пользовательском `PATH`); ядро
`esp8266:esp8266` установлено.

Сборка (из корня проекта):

```powershell
arduino-cli compile --fqbn esp8266:esp8266:generic .
```

Проверка отладочного режима без правки файла:

```powershell
arduino-cli compile --fqbn esp8266:esp8266:generic `
  --build-property "compiler.cpp.extra_flags=-DDEBUG_TEMP_EMULATOR" .
```

Прошивка и монитор (подставить COM-порт):

```powershell
arduino-cli upload --fqbn esp8266:esp8266:generic --port COM3 .
arduino-cli monitor -p COM3 -c baudrate=115200
```

Порты: `arduino-cli board list`. Serial — 115200.

## Соглашения

- Язык комментариев и сообщений — **русский**.
- Стиль: 2 пробела, неблокирующие FSM, никаких `delay()` в горячем пути
  (кроме `safeRestart()` и мягкого сброса Wi-Fi).
- Временные сравнения — только устойчиво к переполнению `millis()`.
- Разделы файла — баннеры `// ===== ... =====`.
- Общую логику (сброс счётчиков, переподключение TCP) не дублировать —
  использовать существующие хелперы.

## Проверка перед коммитом

1. Сборка без ошибок/предупреждений (см. выше).
2. Прогнать компиляцию в обоих отладочных режимах.
3. Для рабочего режима `DEBUG_TEMP_EMULATOR` и `WIFI_SCAN_ONLY` закомментированы.
