Прошивка для **ESP-01 (ESP8266)** — дублёр управления вентилятором охлаждения
автомобиля **Lada Kalina**. Температура охлаждающей жидкости (ОЖ) читается с
диагностического адаптера **ELM327 по Wi-Fi (TCP)**, вентилятор управляется по
гистерезису. Весь код — неблокирующий, на конечных автоматах (FSM), рассчитан
на долгую работу без зависаний.

> ⚠️ **Дисклеймер.** Это дублирующая, а не штатная система управления. Реле
> включается параллельно ЭБУ и в норме «не вмешивается». Устанавливайте на свой
> риск и обязательно проверяйте поведение на столе перед установкой в авто.

## Возможности

- 🔁 **Неблокирующие FSM** для Wi-Fi, TCP/ELM327, инициализации и опроса PID `0105`.
- 🌡️ **Гистерезис** по температуре ОЖ (вкл. 95 °C / выкл. 90 °C).
- 🛑 **Отдача управления ЭБУ**: нет валидных данных 30 с → реле OFF, в чужое управление не вмешиваемся.
- ♻️ **Автовосстановление**: мягкий сброс Wi-Fi → полный `ESP.restart()` при повторных неудачах.
- 🩺 **Детектор «мёртвого TCP»**: серия таймаутов или невалидных ответов → переоткрытие сокета.
- 🧪 **Отладочные режимы**: эмулятор температуры и «только скан Wi-Fi».

## Как это работает

- Пока приходит **валидная** температура ОЖ — работает собственный гистерезис:
  `T >= 95 °C` → реле ON, `T <= 90 °C` → реле OFF.
- Если валидных данных нет дольше `RELEASE_CONTROL_TIMEOUT_MS` (30 с) — реле
  снимается и управление **отдаётся штатному ЭБУ**. Данные вернулись — снова
  берём управление на себя.
- При серии неудач ELM — сначала мягкий сброс Wi-Fi, при повторных — полный
  `ESP.restart()`.
- TCP-соединение с адаптером переоткрывается при серии таймаутов или
  невалидных ответов подряд.

## Оборудование и подключение

| Компонент | Детали |
|---|---|
| Платформа | ESP-01 / ESP8266 |
| Реле | `GPIO2`, активный уровень **HIGH** |
| Адаптер | ELM327 Wi-Fi, TCP `192.168.0.10:35000` |
| Serial | `115200` бод |

**Важно по реле:**
- Нормально **разомкнутое** реле включается **параллельно** штатному управлению
  ЭБУ, поэтому «relay OFF» = *не вмешиваемся*.
- `GPIO2` — boot-strap пин: до `pinMode()` состояние неопределённое. Нужен
  внешний **pull-down** на затвор/базу транзистора реле, чтобы при старте реле
  гарантированно было выключено.

## Сборка и прошивка

Нужны `arduino-cli` (или Arduino IDE / PlatformIO) и ядро `esp8266:esp8266`.

```powershell
# сборка
arduino-cli compile --fqbn esp8266:esp8266:generic .

# прошивка (подставить COM-порт)
arduino-cli upload --fqbn esp8266:esp8266:generic --port COM3 .

# монитор
arduino-cli monitor -p COM3 -c baudrate=115200
```

Список портов: `arduino-cli board list`.

## Настройки

Задаются константами в начале `kalina_fan_control_v2.ino`:

| Константа | Назначение |
|---|---|
| `WIFI_SSID`, `WIFI_PASS` | Точка доступа ELM327 (SSID/пароль) |
| `ELM_IP`, `ELM_PORT` | TCP-адрес адаптера |
| `RELAY_PIN`, `RELAY_ON/OFF` | Пин и уровни реле |
| `TEMP_ON`, `TEMP_OFF` | Пороги гистерезиса, °C |
| `TEMP_MIN`, `TEMP_MAX` | Допустимый диапазон валидной ОЖ |
| `*_TIMEOUT_MS`, `*_INTERVAL_MS` | Таймауты/периоды |
| `ELM_MAX_FAILS`, `SOFT_RESETS_MAX` | Пороги восстановления |
| `POLL_FAILS_TO_RECONNECT`, `POLL_BAD_TO_RECONNECT` | Детектор «мёртвого TCP» |
| `elmInitCmds[]` | Последовательность AT-команд инициализации |

## Режимы отладки

Задаются макросами в шапке `.ino` (по умолчанию оба выключены):

| Макрос | Поведение |
|---|---|
| `DEBUG_TEMP_EMULATOR` | Эмулятор температуры, Wi-Fi/ELM не задействованы. Периодически «окно сбоя» — для проверки отдачи управления. |
| `WIFI_SCAN_ONLY` | Только сканирование Wi-Fi сетей и печать списка (поиск SSID адаптера). |
| *(оба закомментированы)* | **Рабочий режим** с реальным железом. |

## Архитектура

Три конечных автомата, опрашиваемые из `loop()`:

- **Wi-Fi** (`wifiTick`) — `DISCONNECTED → CONNECTING → CONNECTED`.
- **ELM/TCP** (`elmTick`) — `DISCONNECTED → TCP_BACKOFF → INIT_SEND → INIT_WAIT → READY`.
- **Опрос** (`pollTick`) — `POLL_IDLE / POLL_WAIT`, PID `0105` из состояния `READY`.

Общая логика вынесена в небольшие хелперы: реле, таймеры, счётчики неудач,
парсер ответа `0105`. Инициализация ELM327 идёт по таблице AT-команд
(`ATZ`, `ATE0`, `ATL0`, `ATH0`, `ATSP0`).

## Обработка сбоев

- **Таймаут ответа `0105`** в течение `ELM_PID_TIMEOUT_MS` → пропуск опроса; серия
  таймаутов (`POLL_FAILS_TO_RECONNECT`) → переоткрытие TCP.
- **Мусорный ответ** (не `41 05 XX` / вне диапазона) → счётчик невалидных;
  серия (`POLL_BAD_TO_RECONNECT`) → переоткрытие TCP.
- **Отказ AT-команды** (`?`, частый у клонов на `ATE0`) — не рвёт соединение,
  команда пропускается, инициализация продолжается.
- **Серия неудач ELM** (`ELM_MAX_FAILS`) → мягкий сброс Wi-Fi; если и это не
  помогает (`SOFT_RESETS_MAX`), выполняется полный `ESP.restart()`.
- **Таймаут Wi-Fi** (`WIFI_TIMEOUT_MS`) → безопасный рестарт с гарантированным
  снятием реле.
